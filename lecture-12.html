Q5Multiple choice

In MongoDB, a collection is equivalent to what in SQL?

Correct!

Not quite. The correct answer is A.

Q11Structured

Explain the problems with SQL databases that motivated MongoDB, and list the perks of MongoDB.

Show model answerHide model answer

Problems with SQL:

  • Rigid schema
  • Not easily scalable. It was designed for 1990s technology or worse.
  • Requires unintuitive joins, which are expensive on huge, distributed data

Perks of MongoDB:

  • An easy interface with common languages (Java, JavaScript, PHP, etc.)
  • Database technology that should run anywhere (VMs, cloud, etc.)
  • Keeps the essential features of an RDBMS while learning from key-value NoSQL systems
  • Open source and document-based, with high performance, high availability and automatic scaling
Q12Structured

Describe the MongoDB data model: documents, BSON and collections.

Show model answerHide model answer
  • Document-based: data is stored as documents, with a maximum of 16 MB each.
  • Documents use the BSON (binary JSON) format and consist of field-value pairs. Values can be embedded documents or arrays.
  • Each document is stored in a collection. Collections are like the tables of a relational database and share a common set of indexes.
  • Documents in a collection do not have to have a uniform structure, so different documents can have different fields.

Q14Structured

Explain the special characteristics of the _id field and the ObjectId type. Also give two rules for field names.

Show model answerHide model answer
  • By default every document contains an _id field, which acts as the primary key of the collection.
  • Its value is unique and immutable, and it can be any type except an array.
  • The default type is ObjectId, which is small, likely unique, fast to generate and ordered. Sorting on ObjectId is roughly the same as sorting by creation time.

Field-name rules: field names cannot start with $ and cannot contain .. The name _id is reserved for the primary key.

Q15Structured

Write the mongo shell commands to (a) check which database you are using, (b) show all databases, (c) switch to or create school, and (d) list its collections. Why might school not appear in show dbs straight after use school?

Show model answerHide model answer 
db                 // (a) current database
show dbs           // (b) all databases
use school         // (c) switch to / create "school"

Databases are not actually created until you insert data, so school only appears in show dbs after a document has been inserted.

Q16Structured

Write MongoDB commands to insert into products (a) the single document { item: "card", qty: 15 } and (b) the pencil, pen and eraser documents in one command. Explain how save() differs from insert().

Show model answerHide model answer 
// (a) one document
db.products.insert( { item: "card", qty: 15 } )

// (b) several documents: pass an array
db.products.insert([
  { _id: 11, item: "pencil", qty: 50, type: "no.2" },
  { item: "pen", qty: 20 },
  { item: "eraser", qty: 25 }
])

Documents without _id get an ObjectId automatically. Adding a field name that is new to the collection is fine in BSON. save(<document>) inserts if the document has no _id or its _id is not in the collection; otherwise it updates the existing document.

Q17Structured

Convert each SQL statement into a MongoDB command.

SELECT * FROM products;
SELECT * FROM products WHERE item = 'card' AND qty < 30;
SELECT * FROM products WHERE item = 'card' OR qty < 30;
UPDATE products SET qty = 40 WHERE item = 'pen';
DELETE FROM products WHERE item = 'eraser';
Show model answerHide model answer 
db.products.find()
db.products.find({ item: "card", qty: { $lt: 30 } })
db.products.find({ $or: [ { item: "card" }, { qty: { $lt: 30 } } ] })
db.products.update({ item: "pen" }, { $set: { qty: 40 } })
db.products.remove({ item: "eraser" })

Comma-separated conditions mean AND. Use $or with an array for OR. find() returns a cursor, and the shell shows the first 20 results.

Q18Structured

Explain the update options $set, multi: true and upsert: true. What happens if you call update() with a plain document (no $set) as the second argument? How do you remove only the first matching document?

Show model answerHide model answer
  • $set: sets the given field(s) to new values and leaves the other fields unchanged.
  • { multi: true }: updates all matching documents, not just the first.
  • { upsert: true }: creates a new document when none matches the search criteria.
  • A plain document without $set replaces all field-value pairs. It overwrites the entire contents of the document and removes any fields you did not include.
  • Remove only the first match: db.<collection>.remove({<field>:<value>}, true).
db.students.update({ year: 2 }, { $set: { status: "active" } }, { multi: true })
Q19Structured

Using the Employee collection, write queries to (a) find employees named Smith, (b) find employees with Employeeid greater than 2, (c) sort all employees by Employeeid in descending order, (d) return only EmployeeName without _id, and (e) find documents that have a salary field.

Show model answerHide model answer 
db.Employee.find({ EmployeeName: "Smith" })               // (a)
db.Employee.find({ Employeeid: { $gt: 2 } })              // (b)
db.Employee.find().sort({ Employeeid: -1 })               // (c) -1 = descending
db.Employee.find({}, { EmployeeName: 1, _id: 0 })         // (d) projection
db.Employee.find({ salary: { $exists: true } })           // (e)

In sort(), 1 means ascending and -1 means descending. In a projection, 1 includes a field and 0 excludes it.

Q20Structured

Explain what each command does and state what is left in the user collection at the end. Assume it started empty.

> db.user.insert({ first: "John", last: "Doe", age: 39 })
> db.user.find()
> db.user.update(
    { "_id": ObjectId("51...") },
    { $set: { age: 40, salary: 7000 } }
  )
> db.user.remove({ "first": /^J/ })
Show model answerHide model answer
  • insert(...) adds a document for John Doe, age 39. MongoDB adds an _id (ObjectId).
  • find() returns all documents and shows John's document with its generated _id.
  • update(...) finds the document by _id and uses $set to change age to 40 and add a new field salary: 7000.
  • remove({ "first": /^J/ }) deletes every document whose first field starts with “J” (a regular expression).

Final state: John's document matches /^J/, so it is removed and the collection is empty.
