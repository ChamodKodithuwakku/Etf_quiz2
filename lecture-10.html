Q11Structured

Define REST. Explain what a resource and a URI are in REST, with an example.

Show model answerHide model answer

REST (REpresentational State Transfer) is an architectural pattern. In REST you work with resources instead of web pages.

  • Resource: any object the server can provide information about, such as a student, an order or a flight booking.
  • URI: each resource has a unique identifier (URI) that is used to access it.

Example: http://www.gogo-air/reservations/premier identifies the premier-member reservation service. /students/5 could identify the student with id 5.

Q12Structured

In the airline telephone reservation example, describe Approach 1 and Approach 2.

Show model answerHide model answer

The airline wants premier members served immediately, frequent flyers given expedited service, and everyone else given regular service.

  • Approach 1: “Press 1 for Premier, Press 2 for…”. There is one telephone number. An automated message asks customers to press 1 (premier), 2 (frequent flyer) or 3 (others), and the call is routed to the matching representative.
  • Approach 2: “Telephone numbers are cheap! Use them!”. There are separate numbers, e.g. 1-800-Premier, 1-800-Frequent and 1-800-Reservation, so each group calls its own representative directly.
Q13Structured

Describe the two approaches for the web-based airline reservation service. Which one is the REST design pattern, and why?

Show model answerHide model answer
  • Approach 1: one-stop shopping. There is a single URL. The web service must examine every incoming request to determine its priority and then process it.
  • Approach 2: “URLs are cheap! Use them!”. There is a separate URL for each group, e.g. /reservations/premier, /reservations/frequent-flyer and /reservations/regular.

Approach 2 is the REST design pattern. Each resource (service) is uniquely identified by its own URL, which follows Axiom 0. Clients go straight to the right resource, and the service no longer has to inspect each request to decide its priority.

Q14Structured

State Tim Berners-Lee's Web Design Axiom 0. Explain the two fundamental aspects of REST it leads to, and list five things that can be a resource.

Show model answerHide model answer

Axiom 0: all resources on the Web must be uniquely identified with a URI.

  • Resources: every distinguishable entity is a resource.
  • URLs identify resources: every resource is uniquely identified by a URL.

Examples of resources: a web site, an HTML page, an XML document, a web service and a physical device.

Q15Structured

Name and explain the three fundamental aspects of the REST design pattern.

Show model answerHide model answer
  • Resources: every distinguishable entity, such as a page, document, service or device, is a resource.
  • URLs: every resource is uniquely identified by a URL (Axiom 0).
  • Simple operations: a small, standard set of HTTP operations acts on resources: GET (read), POST (create), PUT (update/replace), PATCH (update/modify) and DELETE.

Q18Structured

For a /customers REST API, give the expected response status for: (a) GET /customers (b) GET /customers/99 when customer 99 does not exist (c) POST /customers that adds a customer (d) POST /customers/{id} when that resource already exists (e) DELETE /customers on the whole collection (f) a PUT /customers/5 that succeeds.

Show model answerHide model answer
  • (a) 200 OK with the list of customers (use pagination, sorting and filtering for big lists)
  • (b) 404 Not Found: the ID was not found or is invalid
  • (c) 201 Created with a Location header linking to /customers/{id}
  • (d) 409 Conflict: the resource already exists
  • (e) 405 Method Not Allowed, unless you really want to delete the whole collection
  • (f) 200 OK or 204 No Content

Q20Structured

“In REST, you use resources instead of web pages.” Explain this statement and give three example resources with suitable URIs for a university system.

Show model answerHide model answer

A traditional site is built around pages that a user navigates. A REST service is built around resources, the things (data) the server knows about. Each resource has its own unique URI, and clients use simple HTTP operations on that URI to read or change it. Any kind of client can use the same resource, whether it is a web page, a mobile app or another server.

ResourceURI
All students/students
One student/students/{id}
Courses of a student/students/{id}/courses
One lecture/courses/{code}/lectures/{no}
